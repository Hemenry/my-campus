## 1. 产品理解

### 1.1 要解决的问题

校园学习工具是碎的：错题在一个地方、PDF 词书在网盘里、背诵打卡靠纸质本、试卷资料靠群文件、问问题靠刷聊天记录。碎片带来的不是「找不到功能」，而是**协作成本**——一个问题问出去没人接、接住了答案又散了、散了的资料下次还得再找一遍。

### 1.2 定位

GeekCampus 是**校园学习的统一入口**：把「记录 → 求助 → 沉淀 → 复习」串成一条闭环。

四个一级入口各承担闭环中的一段，职责不重叠：

| 入口 | 在闭环中的角色 | 一句话职责 |
|---|---|---|
| 广场 | 连接同伴 | 把问题、错题、资料丢进公共池，换取同伴的答案与补充 |
| 英语 | 形成复习习惯 | 把 PDF 词书变成个人词卡，用打卡把「看过的」变成「记住的」 |
| 消息 | 闭环的回流 | 回答、评论、采纳的反馈都回到这里，形成再来一次的理由 |
| 我的 | 沉淀 | 有价值的内容存进个人空间，可查、可重做、可复习 |

### 1.3 核心用户

希望提问交流、整理错题、共享资料并跟踪学习进度的在校学生。按使用动机分三类，设计上要同时照顾：

| 用户类型 | 主要动作 | 最在意 |
|---|---|---|
| 求助者 | 发问题、发错题、看回答 | 有没有人答、答得对不对 |
| 贡献者 | 答题、发资料、被采纳 | 被认可、能积累 credibility |
| 自律学习者 | 导词书、每日打卡、整理错题 | 进度看得见、别断签 |

### 1.4 成功标准

设计是否需要返工，用这几条判断（当前无埋点，作为后续验证目标）：

- 一条求助从发布到收到首个回答的路径不超过 3 次点击可达。
- 英语模块从「进入 tab」到「开始翻卡」不超过 2 次点击。
- 「我的」里能覆盖用户产生过的所有内容类型（发布 / 错题 / 资料 / 收藏 / 词书）。
- 任意页面在无数据、加载中、失败三种状态下都有明确反馈，不出现白屏。

## 2. 设计原则

1. **内容优先，界面退后。** 卡片本身不抢戏：白色卡面、细边框、克制阴影，让题目文字和图片是页面里最重的东西。
2. **一个入口一个动词。** 首页四个快捷入口分别是「求助 / 上传错题 / 背单词 / 找资料」，动词清晰，不出现「学习中心」这类模糊命名。
3. **反馈必须即时。** 打卡成功、采纳成功、上传成功都要有明确的状态变化，不靠用户猜。
4. **沉淀是默认动作。** 收藏、加入错题本、加入计划都放在内容详情页的一级位置，让「存下来」比「划过去」更容易。
5. **青绿只给主操作。** 主色只用于主按钮、选中态、进行中的学习任务；标签、分类用低饱和功能色，避免整屏泛绿失去焦点。

### 3.2 导航规则

| 规则 | 说明 |
|---|---|
| 底部导航常驻 | 四个 tab 全局常驻，二级页不显示底部导航，改为左上返回 + 页面标题 |
| Tab 状态保持 | 切换 tab 保留各 tab 的滚动位置与筛选状态，回退不重置 |
| 发布入口唯一 | 广场首页右上角「＋」是唯一发布入口，二级页不重复放发布按钮 |
| 详情页可深链 | 消息、分享卡片、搜索结果都直接跳到内容详情，返回时回到来源 tab 而非广场首页 |
| 登录时机 | 浏览不拦截，收藏 / 发布 / 回答 / 打卡时才拉起授权，授权后原地恢复操作 |

## 4. 主流程

### 4.1 求助闭环（广场为主）

1. 用户在 T1-01 点四宫格「发起求助」→ T1-06 填题干、传图、选学科。
2. 发布成功 → T1-10 → 回到广场「求助」tab，自己的帖子置顶标记「我发布的」。
3. 同伴在 T1-03 看题 → T1-04 写回答。
4. 作者在 T3-01 收到「有人回答」→ 跳 T1-03 看回答 → 采纳一条。
5. 被采纳者收到采纳通知；该回答进入内容详情置顶区。
6. 作者可把整条问题「加入错题本」，进入个人沉淀。

**关键约束**：采纳只能由提问者操作且仅一次；采纳后仍可继续回答，但不再改变采纳状态。

### 4.2 英语：PDF → 词卡 → 打卡

1. T2-01 点「导入新词书」→ T2-03 选择 PDF。
2. 识别中显示进度；完成后自动跳 T2-04。
3. T2-04 校对：低置信度词条高亮置顶，逐条确认，空释义的条目必须处理才能生成。
4. 生成词书 → T2-05 词书详情，展示掌握度分布。
5. T2-06 背诵卡：正面单词 + 音标 + 发音，翻面看释义例句，三档评级决定下次出现间隔。
6. 一组结束 → T2-07 结果页，当天首次完成触发打卡，连续天数 +1。
7. T2-08 日历上留下记录，形成可视的坚持感。

**关键约束**：识别失败可重传，已校对内容本地暂存不丢失；退出背诵中途需二次确认并保留进度。

### 4.3 沉淀与复习（我的为主）

- 收藏（T4-09）是轻量沉淀，错题本（T4-03）是重沉淀，两者可互相流转：收藏的题目可「整理到错题本」。
- 错题可挂到学习计划（T4-06），计划把「每周做多少题 / 背多少词」变成有截止日的任务。
- 学习记录（T4-11）只做展示，不产生新的操作负担。

### 4.4 异常与边界

| 场景 | 处理 |
|---|---|
| 未登录点收藏 / 发布 / 回答 / 打卡 | 拉起授权弹层，成功后原地续做，不跳页丢失输入 |
| 弱网或断网 | 请求层统一超时 8s，失败展示行内重试；背诵卡降级为本地队列，恢复网络后补传 |
| PDF 识别失败 | 保留原文件，提供「重新识别」与「改用手动录入」两条出路 |
| 图片上传中断 | 单张失败可单独重试，不影响其他已成功的图 |
| 内容被删除或下架 | 详情页展示「内容已不可见」并提供返回，不报错白屏 |
| 重复提交 | 发布 / 回答 / 打卡按钮点击后立即置 loading 并防重，服务端幂等键去重 |
| 空列表 | 每种空态都有具体文案 + 一个明确动作（如「还没有错题，去上传第一道」） |

### 5.7 关键组件细则

**今日学习卡（首页视觉锚点）**
- 容器：`--brand-100` 底、`--radius-xl`、内边距 16，右侧插画绝对定位不参与布局。
- 结构：`✦ 今日学习 · 英语` → `还有 12 个单词待复习`（H1，数字加粗且用主色）→ `已连续打卡 6 天，继续保持`（Caption，`--text-2`）→ `开始复习 ›`（Body-Strong，`--brand-600`）。
- 已完成时整块替换文案为「今天的单词已经复习完 · 打卡已记录」，按钮改为「看看打卡记录」，底色转 `--brand-50`。

**内容卡（广场列表）**
- 作者行高 40。右侧类型标签用功能色浅底，文案跟随分类（求助 / 错题 / 资料 / 试卷）。
- 摘要最多 2 行，超出省略；带图时图片等比高度 160，圆角 `--radius-md`，最多显示 1 张，多图在右下角标「共 3 张」。
- 互动栏：评论数、点赞数、收藏图标右对齐。数字为 0 时仍展示，保持行高稳定。

**背诵卡**
- 卡片占屏宽减 32，最小高度 420，垂直居中。
- 正面：单词 32/600 居中，下方音标 14 `--text-2` + 发音按钮；底部提示「点击卡片查看释义」。
- 背面：单词 20/600、释义 16、例句 14 斜体浅色。背面出现后评级按钮才可点，防误触。
- 三档评级：不认识（`#E05B5B`）/ 模糊（`#D9A426`）/ 认识（`--brand-600`），等宽三列。

### 5.8 动效

| 场景 | 时长 | 曲线 | 说明 |
|---|---|---|---|
| 卡片按压 | 120ms | ease-out | 缩放至 0.98 |
| 页面切换 | 250ms | cubic-bezier(.22,.61,.36,1) | 右进左出 |
| 背诵卡翻转 | 400ms | cubic-bezier(.4,0,.2,1) | Y 轴 3D 翻转 |
| 打卡成功 | 600ms | ease-out | 数字滚动 + 主色扩散波纹 |
| 列表加载 | 300ms | ease-out | 卡片依次上浮 8px 淡入，间隔 40ms |
| 底部弹层 | 280ms | cubic-bezier(.22,.61,.36,1) | 上滑 + 遮罩淡入 |

尊重系统「减弱动态效果」设置，开启时只保留透明度过渡。

### 5.9 可用性与无障碍

- 所有可点区域不小于 44×44。
- 正文与背景对比度不低于 4.5:1；`--text-3` 仅用于占位与禁用，不承载信息。
- 颜色不作为唯一信息载体：错题状态点同时带文字（已掌握 / 待复习），打卡用图标 + 数字双表达。
- 表单错误提示放在字段下方，不用仅靠 Toast 告知。
- 图片必须带替代文案，题目图片支持点击放大查看。

## 7. 技术架构建议

### 7.1 方案取舍

| 方案 | 做法 | 优点 | 代价 | 结论 |
|---|---|---|---|---|
| A. 微信小程序原生 + 自建轻量 store | WXML/WXSS/JS，`behaviors` 抽公共逻辑，`mobx-miniprogram` 管状态 | 包体小、性能稳、无编译层、和官方能力贴得最近 | 组件复用靠约定，跨端要重写 | **推荐** |
| B. uni-app（Vue 3） | 一套代码多端 | 跨端、生态好、团队若熟 Vue 上手快 | 引入编译层，调试链路变长，小程序端仍有兼容坑 | 备选（未来要 H5 时再迁） |
| C. Taro（React） | 一套代码多端 | 组件化能力强 | 包体与调试复杂度更高，团队技术栈若不匹配成本高 | 不推荐起步用 |

选 A 的理由：这是个纯小程序产品，没有跨端诉求；四个 tab 的交互以列表和表单为主，不需要重框架；统一性靠「组件库 + 请求层 + store」三层约定就能拿到，不必为此引入编译层。

### 7.2 目录结构

```
miniprogram/
├── app.js / app.json / app.wxss
├── components/            # 统一组件库（严格按 5.6 清单落地）
│   ├── nav-bar/           # 顶部品牌栏与通用标题栏
│   ├── search-bar/
│   ├── quick-grid/
│   ├── today-card/
│   ├── segment-tabs/
│   ├── post-card/
│   ├── file-card/
│   ├── mistake-card/
│   ├── answer-card/
│   ├── word-card/         # 背诵卡
│   ├── word-entry-row/    # 词条校对行
│   ├── btn/  chip/  avatar/  empty/  skeleton/  toast/  sheet/
├── pages/
│   ├── plaza/  english/  message/  mine/
│   └── detail/ publish/ search/ auth/ webview/
├── store/                 # user / plaza / english / message
├── utils/
│   ├── request.js         # 统一请求层
│   ├── auth.js            # 登录与授权恢复
│   ├── storage.js         # 持久化封装
│   └── format.js
├── styles/
│   ├── tokens.wxss        # 第 5 章全部 token 落为 CSS 变量
│   └── mixins.wxss
└── assets/icons/
```

**约束**：页面文件不写业务常量（颜色、字号一律引用 `tokens.wxss`）；页面不直接调 `wx.request`；跨页共享状态只走 store，不走 `getApp().globalData`。

### 7.3 请求层

统一封装 `request(options)`，集中处理六件事：baseURL 与超时（8s）、登录态注入、`code !== 0` 的业务错误归一、401 触发静默续期并重放一次、并发重复请求合并、失败统一抛出可展示的 `message`。

页面侧统一用「加载中 / 成功 / 空 / 失败」四态包装器，避免每个页面各写一套 loading 逻辑。

### 7.4 状态与持久化

| 层 | 存什么 | 落地 |
|---|---|---|
| 内存 store | 当前用户、各 tab 列表分页游标、筛选状态、背诵会话进度 | `mobx-miniprogram` |
| 本地持久化 | 登录态、搜索历史、草稿（发布 / 回答）、背诵未完成队列、打卡缓存 | `wx.setStorageSync`，草稿按页面 + 时间戳分键 |
| 服务端 | 内容、词书、打卡记录、通知 | 接口 |

关键约定：草稿在输入停止 1s 后自动落本地，返回时提示「已恢复上次编辑」；背诵中断时把当前会话写入本地，恢复网络或下次进入时询问是否继续。

## 8. 验收标准

设计交付后，按这几条检查是否达到可用：

1. 37 个页面全部有明确入口与返回路径，不存在只能通过分享进入的孤岛页。
2. 四条主流程（求助、PDF 导入校对、背诵打卡、错题沉淀）在无网络、空数据、失败三种情况下都有明确下一步。
3. 主色在单屏内出现不超过 3 处，且都对应主操作或选中态。
4. 所有列表在 0 条、1 条、多条、加载更多四种情况下布局不塌陷。
5. 组件清单里的每一项都能在页面清单里找到明确使用位置；只被一个页面用一次的组件，降级为该页面内部片段，不进公共库。
6. 设计 token 全部有变量名，页面样式中不出现裸色值。
